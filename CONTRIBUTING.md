# Contributing

This repository contains a working proposal. Read [LICENSING.md](LICENSING.md) before submitting material: redistribution and contribution terms are not yet settled.

Use an issue to report unclear meaning, a conflicting calculation, missing evidence handling or an interoperability problem. Include a synthetic example, expected interpretation, relevant draft section and the impact on an independent implementation.

## Propose a change

1. Read the affected specification and fixtures.
2. For semantic changes, copy [the RFC template](rfcs/0000-template.md) into a new numbered proposal and discuss it.
3. Update text, schemas, examples and expected results together when the change is accepted.
4. Describe compatibility impact and the validation performed in the pull request.

Keep data fictional. Do not commit credentials, personal survey responses, private payloads, source code from customers or proprietary questionnaires.

Research definitions, proposed OEMS policy and implementation-specific choices must be distinguished. Include primary-source links for externally attributed claims. A metric change needs examples covering ordinary data, no observations and incomplete evidence.

## Review

Reviewers check meaning, consistency, interoperability, privacy and whether examples match the proposed rules. Editorial preference alone is not a semantic objection. Record unresolved issues instead of concealing them in prose.

Language-specific helpers may be added later, but the normative contract must remain understandable and implementable without them.
